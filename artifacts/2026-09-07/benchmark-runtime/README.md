# 共享包与内存配置的原生性能测试入口

2026-09-07，`benchmark_pipeline.py` 已接入 schema-3 共享包、运行时尺寸及线程、设备、权重放置、加载和 RAM 缓存选项。新增轻量原生 `--report-json`，让关闭张量 trace 的运行也返回实际文本桶、来源尺寸、GPU 索引和内存请求统计。**真实 512×512 八步生成完成，PNG 与已验证原生基线逐字节相同；这是一轮测试工具集成和输出回归，不是重复配对性能结论。**

## 实现与检查

- `cli/generation_report.*` 只依赖公共标准 C++ 类型，负责 JSON 转义及独占创建新文件。公共 `GenerationResult` 在末尾增加实际包/来源/文本配置和 Vulkan 索引；流水线在真实分词选桶后更新它们。没有修改模型数学、精度、权重或调度。
- `tools/benchmark_request.py` 复用固定包完整验证、共享 CAS 完整验证和已有的源选择规则。宽高必须符合当前包约定；固定包不会被当作可变尺寸。生成结束后由实际 token 数绑定最终来源，并与原生报告交叉检查。
- 原生请求明确传递尺寸、线程、GPU、文本归约、GPU/RAM 策略及加载/缓存预算。结构化报告提供实际选择与计时，不从可能包含多行提示词的终端文字认定它们。
- 保存的 FP32 噪声先检查字节数和有限值。可执行文件及输入使用快照，结束后复核快照和包清单身份；缺失报告、配置不符、错误输出尺寸、未完成去噪、改变输入均不能成为成功结果。原有 img2img 原始/解码图像身份约定和 `port_metrics.py` 正式协议保持。
- 原生 GPU 索引与 NVIDIA 采样索引分开；后者明确是整卡诊断，可以通过 `--no-gpu-sampling` 关闭。开启 trace 或使用分配诊断构建的单次结果不得进入正式速度轮。

首次 CPU/Vulkan 各 6 项相关 CTest 全部通过，包含 CLI、公共 API、请求校验、真实 C++ JSON 写入/解析，以及安装后的外部 C++ 消费者。Python 原有测量测试 21 项、新增请求/报告测试 9 项、共享选择测试 6 项通过。源码和工具冻结后进行完整运行，固定 669 个源码、工具、程序和输入身份；运行期间没有修改冻结文件。全部检查无失败或跳过。

## 实际运行

运行使用独立的程序与工具快照，隐藏原项目、禁网、模型和工具快照只读。Python 测量工具参与调度，真正的生成子进程仍为原生 C++。相同 15-token 苹果提示词、source32/64 DiT 槽、保存噪声、512×512、8 步 Vulkan FP32、CPU direct VAE、2 线程、GPU0；`--model-loading mapped --dit-weights auto --gpu-reserve-mib 8192 --dit-cache-mib 6144 --ram-reserve-mib 3072`。8192 MiB 用来主动选择 RAM 分支，所有预算都是实验设置，不是模型硬件要求。

Python 在计时前完整读取并校验全部模型文件，这可能预热页缓存；原生过程内部仍再次完整校验。此轮没有控制文件缓存或后台负载，且单轮没有配对重复。之前384.364秒的 traced监督区间与本轮386.854秒的原生子进程区间不在同一计量范围，不能直接计算速度变化。

本轮没有生成25个中间张量，因此不新增全张量或官方质量通过数。它只重用已验证原生基线进行 PNG 字节回归。`formal_comparison_eligible=true` 表示单次输入、配置、trace和构建满足工具检查的前提，不代表已完成 S/M 协议。
