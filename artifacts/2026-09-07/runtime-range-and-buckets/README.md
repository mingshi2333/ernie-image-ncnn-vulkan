# 实验性运行时范围、文本桶与最大序列资源测试

本轮把 F1 的通用范围和实际分词后选桶接入原生流水线，并建立最大序列单块的资源证据。完整 canary 图像矩阵仍未完成，不能据此宣称完整范围的图像质量或已超过参考项目。既有官方数值容差未变；这些数值由助手为本项目选择，不是官方标准，也不是用户明确指定的门槛。

## 原生改动

- schema-3 接受轴长 16..2048、16 倍数、面积至多 2097152 的实验性范围。ModelPackage 保留源配置，ShapePlan 检查目标几何、有效文本、padding 和 checked arithmetic。仅完整规范化 SHA 已知的图可替换枚举形状字段。
- Rust 完整验证全部共享对象后保存轻量来源索引。实际分词（以及可选 PE）结束后，按 token 数选择包内最小独立导出的 32/64/2048 模板；选择不重复读入/散列 23GB 权重。
- 32-token 来源是原 `portable-turbo1024-s32-v1`，manifest SHA `9cc1dc0e605256e405a049b6a8d58f98a9f138b2a16c6d40be6bb35595743154`。64 个实际图逐一匹配原文件 SHA 与规范化图 SHA；71 个非图文件的 manifest 绑定与 s64 来源相同。包构建随后完整重算实际权重校验。
- 32-token 来源保留 64 个 DiT 文本槽。实际文本、编码桶、DiT padding 分别记录，不把 padding 算作有效文本。
- 总序列大于 6144 时，Vulkan 用 ncnn 的 host-resident weight 模式。CPU 不受此 Vulkan 策略影响。旧 schema-1/2 固定配置及转换器的 6144-token 保护保持。
- VAE encoder 的目标尺寸注册独立于 decoder/text 模板选择。换文本桶可保留正确尺寸 encoder，不会暴露其他尺寸 encoder。新的三来源包不包含 encoder。
- `shape-plan` 加入静态 SDK 依赖导出；本轮未重跑新版本 SDK 安装/消费者验证。allocation-instrumented 构建正确拒绝 SDK 开关，已恢复原配置。

## 最大序列：运行状态和数值状态分开

同一官方 block0、同一组已保存的输入；对应 2048×1024、8192 图像位置和 2048 文本位置，总计 10240。hidden/AdaLN 是固定种子的合成输入，使用真实官方权重及位置频率；没有运行 heads、36 层连续链、8 步或图像解码。官方 CPU forward 26.828 秒，输出全部有限。

| 原生模式 | 执行结果 | 整卡显存采样峰值 | 数值对照 |
|---|---|---:|---|
| 权重放 GPU | supervisor 主动终止，退出 -9 | 6506 MiB | 未产生完整输出，未做数值通过判定 |
| 权重放系统内存 | 原生退出 0，完整输出 | 5609 MiB | 41943040 元素全部有限；NRMSE 2.75455164e-6，最大绝对差 0.015869140625；通过不变的旧容差 |

两次都使用同样的 16GiB cgroup、swap=0、整卡 6144MiB 保护线、主机至少 3GiB 可用内存和 1800 秒上限。GPU 数字包含桌面及其他进程；离散采样可能超过保护线后才终止。两次观测到的 cgroup OOM/OOM-kill 都为 0。第一行表示项目保护线触发，不是已证明 8GB 显卡物理容量不足，也不是数值误差失败。

host 模式完整 supervisor 用时 9.695 秒，cgroup memory.current 采样峰值 1796833280B、最低主机可用 14279503872B。memory.current 含文件缓存，不是 RSS。默认模式中止，因此不能从两行推算运行速度或显存峰值的相对改善百分比。

`root-comparison.json` 使用不同分块大小独立重算全部 41943040 元素。原结果、原保护线中止、输入 fixture、冻结计划和执行脚本分别保存在 `device-weights/` 与 `host-weights/`。权重、二进制及大张量留在本地 outputs/models，未进入 Git。所绑定的源码/实现及运行版本不等于完整驱动/系统软件封闭性证明。

## 图契约和回归

`graph-matrix.json` 保存三个已验证来源 × 13 组尺寸 × 64 个实际 C++ 图的 2496 个结果，并由 Python 按目标尺寸独立重算完整规范化图 SHA。尺寸是十个计划 canary 加 16×16、16×2048、2048×16。它验证参数实例化，不代替这些尺寸的实际模型执行。

C++ 五项相关 CTest 通过，Rust 六项共享包检查通过，Python pipeline-package 六项、pipeline-reference 八项、dynamic-package 二十一项通过。新增选桶测试覆盖 32/33、64/65、2048/2049 边界、桶缺失、旧静态包、失败后状态以及 source/target 身份。初次调用错误的构建目标别名及随接口改变需更新的测试假数据保存在 `check-results.json`，没有改生产信任规则来迁就假数据。

## 本地可用包与本轮边界

`models/turbo-shared-v2` 含 88 个独立普通文件对象，23271687765 字节（约 21.67GiB）。manifest SHA `21b6bc8deae17418c22257b52e928ee048a372342a2517bcb954276257c21d1a`。三个源包通过完整 Python 验证，复制后再验证全部 CAS 对象；没有每尺寸再复制整套权重。原 `turbo-shared` 包保持原 manifest。

本轮 64×64 完整原生 smoke 已成功完成，记录在 `native64/`：采用真实 15-token 提示词、自动 32 文本桶/64 DiT padding、原生文本、8 步 Vulkan FP32 与 CPU VAE。原生进程退出0，25个 FP32 张量、320768个元素全部有限，PNG与解码张量量化逐像素一致。supervisor 用时384.779秒，整卡显存采样峰值2715MiB，cgroup峰值5832331264B、OOM0；trace、权重校验和受限CPU配置使它不适合作为正式性能结论。这个 smoke 的目的为实际入口连通性，未配套本轮新形状的官方图像 oracle，因此不能标记完整数值或感知质量通过。实际查看64×64输出为灰色细条结构，未清楚呈现提示词中的红苹果；不能把PNG成功写出当作提示词效果通过。需后续相同配置的官方对照区分低分辨率模型表现与实现差异。
