# 共享 768 首次预测：块 17～19 的相同输入对照

上一轮观察到块 17～19 的相对误差连续约翻倍。本轮将进入各块的隐状态、六个调制向量、位置表和 mask 对齐后，**三个块的局部 NRMSE 分别为 7.14e-7、7.43e-7、8.39e-7，比原累计误差小约 13.7、27.5、50.4 倍。** 这支持传入偏差传播和放大是本样例的重要因素，不能把前一轮的增长直接归因为这三个块的局部实现错误。

这仍是局部诊断。没有证明哪项初始差异是最终根因，也没有修复完整轨迹；[原完整 768 对照](../runtime-squares/README.md) 的 18/25 保持。没有调整旧质量阈值或正式语料，位置表观察没有改变生成器实现。

## 实现及实验有效性

现有 `ernie-block-sequence-runner` 新增 `--package ... --block-index 0..35`，从已认证共享包实例化一个块，直接调用现有生产 `run_block_sequence`。该模式读取十个块输入，跳过 heads，保存的 trace 名称采用模型的全局块编号。省略选块参数时仍运行原完整 DiT 路径；原固定目录方式保留。没有复制推理数学或导出新的权重目录。

目标编译通过；10 个实际非法参数调用在读取模型前被拒绝，没有写输出；使用实际 Clang 配置编译不含包支持宏的语法分支也通过。候选 probe 摘要为 `88aaf821aba5a08e1935084953c2a51aad2bb0dc8778ef67bc71fd997f1afa9b`。代码基点为 `77085eb0a22783e7e409ef8d0d1f76a3ebdd7d51`，本轮只有 probe 入口修改，没有生成器数学或默认值变化。

计划 `f5a8b08f09cb31b3cb3629ced64c83f9518f3f5baf940193bf501754f2d2075c` 冻结 336 个源文件和 390 项文件绑定。使用上轮共享 source32 的首次预测，15 个有效文本 tokens、32 文本桶、64 DiT 槽、2368 个总 tokens。所有对照都采用 FP32 和 2 线程，原生显式请求 RAM 权重、stdio、无跨步缓存。

1. 先在 CUDA 计算并保存官方频率对应的 cos/sin；该准备过程没有模型前向，CUDA 张量分配峰值为 3,637,248 字节。
2. 独立执行三个官方块，输出全部逐字节复现旧官方阶段，且内部使用的 CUDA 位置表与所保存的表逐字节相同。
3. 官方进程退出后，执行三个原生单块复现，输入来自旧原生阶段；输出也全部逐字节一致，确认选块入口没有改变这些执行结果。
4. 再执行六次原生对照，分别换入官方隐状态/调制，使用原 CPU 位置表或已对齐的官方 CUDA 位置表。两组均固定原 mask；后一组将所有十个数值输入对齐。

## 数值结果

块编号从 0 开始。表中指标都是相对同一个已保存官方块输出的 NRMSE。

| 块 | 原累计轨迹 | 官方隐状态/调制，CPU 位置表 | 全部输入对齐，CUDA 位置表 | 原累计 / 全对齐 |
|---|---:|---:|---:|---:|
| 17 | 9.787622e-6 | 7.155495e-7 | 7.136946e-7 | 13.7140 |
| 18 | 2.041035e-5 | 7.424978e-7 | 7.427295e-7 | 27.4802 |
| 19 | 4.228584e-5 | 8.349379e-7 | 8.391165e-7 | 50.3933 |

完全对齐后最大绝对差依次为 0.00634765625、0.004638671875、0.008544921875；原累计最大差为 1.010620117、2.201416016、4.284423828。隐藏状态参考最大值约 73000，不能把这些数值直接解释为最终图片的像素误差。

每张位置表有 303,104 个值，CPU/CUDA cos 有 64,014 个不同值，sin 有 43,154 个不同值，最大差均为 5.96046448e-8。仅更换位置表后，三个原生输出之间的 NRMSE 为 4.53e-7、4.74e-7、5.61e-7；相对官方的误差没有一致下降。因此，本次没有依据将 CPU 三角函数简单认定为主要问题，也没有将 CUDA 表移入生产。

对齐隐状态和调制是联合干预，不能按上述倍数分配各因素的因果百分比。局部误差变小也不能替代完整生成验收。新结果缩小了诊断范围，后续仍需完成更多实际尺寸执行、完整质量对照和已记录累计误差的合理评估。
