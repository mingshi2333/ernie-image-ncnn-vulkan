# 共享模型包的 768 / 1024 运行时尺寸开发对照

本项使用已冻结的 990e8ef 源码、92559ea4 Linux Vulkan 程序和共享 source32 包，直接在运行时选择新尺寸。原生文本、8 步 FP32 去噪和 CPU direct VAE 均参与；PE 关闭、RAM 权重、stdio、缓存 0、2 线程、trace 开启。官方在 CUDA 上逐块执行 DiT，文本、heads、scheduler、VAE 使用 CPU，禁用 TF32。两边逐尺寸使用同一份保存的初始 FP32 bytes。完整配置和每组 430 项输入/源码/二进制/来源绑定保留在 [预先冻结的协议](../runtime-squares-protocol/README.md)。

## 768×768 已完成

原生和官方均退出 0，8 步去噪及 VAE 全部完成。原生图片为木桌上的红苹果。完整 PNG 最大通道差为 2/255，平均差为 0.0277167426/255，通过原 PNG 诊断门槛。**完整张量检查只有 18/25 通过，仍为数值未通过；没有 OOM 或资源保护终止。**

根任务独立重读 430 项绑定、真实执行记录、请求参数、初始输入、15 个 token IDs，以及全部 13,829,120 个有限元素，重新计算全部张量和 PNG 的差异，确认原比较结果。不是通过复述测试通过数作出结论。官方来源为 source32 `9cc1dc0e…`，源权重证明来自 source64 `72bb195a…`，71 个非图运行资产一致；官方实际加载器逐块核对真实权重散列。768 官方完整 fixture SHA256 为 `731ebbab21841d98635d65e72960804c21cb42007a25928483cf7b069ebffd7f`，已登记为可复用官方参考；登记不改变原生 18/25 的负面结果。

## 1024×1024 已完成

原批次按预设规则在 768 数值比较退出 1 后停止，原主进程已结束，记录没有覆盖。确认两边执行完成、失败属于数值比较而非资源故障后，以独立 `continue1024.py` 继续原先已冻结且尚未执行的 1024 三个步骤；仍使用原计划、输入、二进制、资源保护设置与容差。没有重新运行 768。

1024 原生和官方也均退出 0，8 步及 VAE 全部完成，cgroup max / OOM / OOM-kill 事件均为 0。原生图片同样为木桌上的红苹果。PNG 平均通道差 0.0007610321/255、最大差 1/255，2,394 个通道样本不同，共 3,145,728 个样本。**张量检查为 24/25，唯一未过项是 prediction-7 最大误差 0.0830632，高于原限 0.0586948；其 NRMSE 0.000411374 通过，最终 latent、unpacked、decoded 和 PNG 均通过。**
