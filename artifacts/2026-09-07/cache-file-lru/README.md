# 文件页状态变化与 RAM 权重缓存保留

2026-09-07，修正 Linux 可回收文件页估计对活跃/非活跃列表划分的依赖。相同映射加载、6 GiB RAM 缓存和 512×512 八步生成中，**命中由 13 次增至 42 次，压力回收由 54 次降至 0 次**；25 个张量和 PNG 仍逐字节等于基线。缓存保留在本例有效，**但本次耗时 384.364 秒，前次 378.970 秒，尚无加速证据**。缓存继续默认关闭。

## 依据与改动

旧算法只计入 `inactive_file`。对上一轮 722 份分类采样作叶级 cgroup 回放，有 270 份估计低于 3 GiB 预留；同一批干净文件页进入 `active_file` 后会失去全部估计回收额度。回放不是实际准入时刻，也不包含所有上级限额；它支持修正方向，不独立证明上一轮每次回收的具体原因。原始采样路径、散列和回放范围见 `sample-replay.json`。

Linux 的 `si_mem_available()` 同时考虑两类文件 LRU，并扣除半数缓存与低水位中较小的值。已从官方代码仓库核验固定修订 `df2908090cda368b01ff43709f51890076c56157`，源码身份保存在 `policy-basis.json`。[固定内核源码](https://github.com/torvalds/linux/blob/df2908090cda368b01ff43709f51890076c56157/mm/show_mem.c)

本项目在 `src/host_memory.cpp` 中改为：

1. 对 active/inactive 文件列表求和，使用饱和运算避免溢出。
2. 同时受文件总量减 shmem、cgroup 已用量约束，再扣除 dirty/writeback。
3. 只把剩余干净文件页的一半计入可回收余量，另一半不计入。
4. 继续取主机 `MemAvailable` 和全部有限上级 cgroup 余量的最小值；必需输入失效则关闭准入，可选统计失效则不提供回收额度。

它比内核的文件页贡献项更保守，但不等同于内核完整可用量算法，也不保证立即分配成功。匿名内存、锁定权重、slab 和 swap 不获得额外额度。同样的干净文件页只在两个列表之间移动时，不再改变计算结果。推理数学、权重会话的准入/租约/实际压力回收规则和所有用户参数均保持原样。

## 结论与下一步

预先冻结的本轮要求是保持所有输出一致，同时比前次具有更多命中、更少回收；三项均通过。该要求是开发回归目标，不能代替 O2 的重复净性能收益或 S/M 的正式比较。前次 13 次命中与更早零命中的记录不作修改。

缓存保留改善的同时，文件页限额压力仍然存在，max 事件反而增多；本次耗时也没有低于前次。文件缓存状态未受控，不能把时间差直接归因到本次改动，但同样不能声称加速或降低系统内存。下一步应补齐 `tools/benchmark_pipeline.py` 对共享包、运行时尺寸和新内存选项的支持，再比较同一程序的 mapped/stdio、缓存关闭/开启；速度轮关闭 trace。保留耗时、输出身份、进程 RSS 和文件页压力各自的测量范围。
