# 共享 768×768 首次预测：可复现命令与输入对照

本轮补齐 `tools/diagnose_pipeline_step.py` 的共享包入口，并检查已有 768 开发样例的第一次预测。**保存的原生输入逐字节复现旧输出；换入全部官方准备的输入后，预测差异没有下降。** 这说明早期差异不能简单归因于原生条件准备，下一步需要比较 DiT 内部阶段。尚未定位具体算子，也没有修复完整自由轨迹；原 [768 完整对照](../runtime-squares/README.md) 的 18/25 保持。

## 实现

- 现有 Python 单步命令通过 `validation_package` 选择运行时尺寸和真实文本桶，再通过已登记的完整参考及来源绑定认证共享包。实际计算仍调用上轮已有的原生 `--package` 入口，没有新建另一套推理数学或导出固定模型目录。
- `--threads` 同时控制时间特征准备和原生计算，默认 4；新增 `--host-weights` 显式请求 RAM 权重。原 schema-1/2 路径继续完整验证固定包，并传递 36 blocks 和两个 heads。
- 时间特征观察程序接受可选的 0..7 步号，省略时仍取第 6 步。实际默认值和显式第 6 步均复现旧特征散列 `5919ea08…`；本轮第 0 步时间值为 1000，特征散列 `0f8858bd…`。调用的是已有生产函数，未改变时间特征公式。
- 20 项 Python 检查通过，包括 6 项新命令/来源/损坏输入检查和原有 14 项参考/包检查。时间特征程序编译通过，3 个有效调用和 3 个非法步号调用均符合预期，拒绝的调用未写输出。

命令示例见 [数值诊断文档](../../../docs/NUMERICAL-DIAGNOSTICS.md)。本轮代码基点为 `fae5c1d836d65b1b7abd75ba2fab53802fabc363`，335 项源文件被冻结；实际 probe 仍为 `1d754f49534434cf8e3882b271714060394f5233b6a13eb3a0cf2c7e7bcb665a`。原生生成器数学和默认设置均未改变。

## 两次真实预测

先冻结计划 `d223454f05f387e336e5b37718a61c13b9dcf8339fab5671ceb760c1a5a7d5df` 的 385 项绑定。两次均使用同一个原生 Vulkan FP32 probe、共享 source32、15 个有效 tokens / 32 文本桶 / 64 DiT 填充槽、48×48 packed grid、36 blocks 和两个 heads、显式 RAM 权重、stdio、缓存 0、2 线程。先完成原生复现及独立比较，确认精确相同后才启动第二次。

第二次实际调用新增的 Python 共享包命令，执行包校验、来源认证、官方 CPU 时间特征准备、二进制快照、原生预测和比较。这里的“官方输入”指输入来源；**本轮两次模型计算都是原生 Vulkan，没有重新运行 PyTorch 官方模型。** 期望输出来自之前完整官方参考 `731ebbab…`。

每次输出均有 294,912 个有限 FP32 值。

| 输入来源 | 相对原完整官方预测的 NRMSE | 最大绝对差 | 判定范围 |
|---|---:|---:|---|
| 保存的原生输入 | 3.13661213e-5 | 0.00120186806 | 与原完整原生 `prediction-0` 全部字节相同，复现误差 0 |
| 官方准备的 latent、文本、时间特征、位置表、mask | 4.65636934e-5 | 0.00320696831 | 通过既有单步 NRMSE 0.003 / 最大差 0.067200556 门槛 |

初始 latent 和 mask 的两端字节本来就相同；文本、时间特征、cos/sin 的末位存在差异。更换全部官方准备的条件没有使第一次预测更接近保存的官方输出，不能据此认定原生条件更准确，也不能将各项条件效应线性相加。官方块在 CUDA 上从频率计算 cos/sin，原生使用保存的 CPU 表，这类已知三角函数末位差异仍包含在计算路径对照中。

结合上轮第 6 步的单项替换，只能确定晚期对进入该步的 latent 偏差敏感，而早期在官方准备的输入上也存在 DiT 路径差异；具体引入与放大位置仍待逐阶段定位。没有按本次结果改变精度、步数、权重、历史阈值或正式质量语料。
