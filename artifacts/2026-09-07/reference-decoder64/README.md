# 原始参考项目：64×64 VAE 实际解码

2026-09-07。本机实际运行 futz12 原始程序的 `--decode-latents`，分别执行 CPU 和 NVIDIA Vulkan FP32 解码，两次返回 0 并产生 64×64 PNG。它们使用同一份保存的官方最终 latent，均通过本项目历史像素规则。该结果是独立解码组件比较，未运行参考项目的文本编码或八步去噪，也没有完成端到端速度、内存或整体画质比较。

## 门槛解释与剩余范围

`pixel_mae ≤ 0.1`、`pixel_max ≤ 2` 是助手为本项目制定的历史数值诊断规则，未经过跨后端波动和感知质量标定；它们不是 ERNIE、ncnn 或参考项目规定的画质标准。此次两项通过只说明这个固定小尺寸解码在该规则内，不能用于认定高分辨率、长提示词或完整去噪也通过。详见[门槛来源](../../../docs/NUMERICAL-DIAGNOSTICS.md#门槛的来源与适用范围)。

参考项目 decoder 的逆 BN 使用 `1e-4`，官方 ERNIE 使用 `1e-5`，此前权重审查已保留该差异。此次保持双方原实现，不能称为已证明完全相同数学的对照。原始解码入口只输出 PNG，未导出其 raw decoded 浮点张量；因此不凭 PNG 成功断言参考项目内部所有值有限，也不将九个通道差异归因于单个算子。

参考项目完整生成的常驻权重下限仍超出本轮安全预算；这是源代码/资产分析，不是实测 OOM，见[容量记录](../../2026-09-06/reference-weight-identity/capacity-preflight.json)。本次没有尝试其完整模型，也不能把无法测量的速度比视为胜出。

`png-review.json` 保存全部统计、进程结果和门槛来源；`review_png.py` 可在原始运行文件仍在本机时重新核对所有绑定并计算结果。`source-review.json` 另外记录两次运行后的原始 peer/ncnn 源码身份检查。生成图片、模型权重和二进制保留在本地输出目录，不纳入 Git。
