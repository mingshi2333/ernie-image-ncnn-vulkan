# Linux CLI local delivery draft

**Not distributable; not published.** This artifact records a local packaging
exercise, not permission to redistribute code, model weights or dependencies.
No public URL exists. Models, SDK, system libraries, source checkout and Python
environment are not bundled.

The real candidate is `outputs/delivery-candidate-v2`, generated by its frozen
`outputs/delivery-candidate-v2-execution/build_release.py` from the read-only
moved Linux Vulkan D1 v2 installation. The four selected install files match
D1's recorded hashes. Frozen source identity is
`70faadbee76bc31f7728c010d1e9371d99a2e2aefa8e7bdc74ef60847645c811`.
Both build/source and selected install evidence are linked in `release.json`.

The archive is 10.672 MiB. All 181 extracted payload files were independently
checked for exact inventory, SHA256 and size. `files.json`, `SHA256SUMS` and
`extraction-result.json` retain that evidence without committing the binary.
The actual CLI was not executed during packaging; earlier D1 evidence covers
only installed API, linkability, CLI help/diagnose and bad-model rejection.

161 project/upstream/Rust notice texts were collected. Fixed ncnn/glslang Git
objects and Cargo.lock-authenticated local crate archives provide the recorded
license bytes. Additional system notices come from local RPM candidate packages.
Those records do not establish actual transitive loader resolution, complete
static attribution or redistribution permission. The manifest remains
`licenses_complete=false`; four lockfile packages lack local cached source and
some zlib/libstdc++ packages lack installed notice texts. Platform verification
for a distributable release remains pending. No Windows/macOS or full-model
claim is made.

The first `outputs/delivery-candidate-v1` remains intact: it used a conservative
unsupported Cargo cache lookup and reported an install-evidence byte-field
mismatch. Version 2 authenticated the available local `.crate` archives and
normalized the real installation `bytes` field. The initial shared-output
symlink-path rejection also remains logged; the successful runs used the
explicit resolved shared-output parent, without weakening symlink checks.
