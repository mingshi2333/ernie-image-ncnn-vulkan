# 保存官方文本特征的完整轨迹诊断

在 `outputs/pipeline512x384-pe-officialtext-fp32-v1/` 实际执行 512×384、Turbo 8 步、Vulkan DiT FP32 和 CPU direct VAE。使用历史 PE 生成的同一提示词、官方文本特征和初始 FP32 latent；原生文本编码与 PE 被绕过，因此该运行属于开发诊断。输入、二进制、脚本和包身份及全部数值结果由 `tools/diagnose_trajectory.py` 调用现有独立审计器重新核对。

注入官方特征后局部最大差通过，但 latent 和 decoded 的 NRMSE 均略增。这说明最终越界对条件误差和后续舍入的交互敏感，不能宣称所有误差均改善，更不能把文本编码判为唯一误差来源。下一步使用真实文本逐层激活与同输入的局部对照定位，而不是根据单个终值盲改归约。

首次越界按实际执行顺序定位：历史路径为 `decoded`；注入特征的诊断没有越界。原生文本路径仍必须重新实现并通过完整 25/25 与 PNG 才能关闭质量项。正式 72 个配对案例尚未运行。

本次记录总运行约 539.7 秒，含 trace 和模型校验，不能用于正式速度结论。`results.json` 保存两条轨迹各 25 个边界的输入身份、官方/原生输出散列、误差和首次失败；`pipeline-result.json` 保存实际运行记录。
